Functions & Closures

Arity overloads, varargs, destructured parameters, closures and function composition — the vocabulary every other module builds on.

Goals
  • Write multi-arity functions with docstrings and varargs.
  • Destructure sequential and map arguments fluently.
  • Create closures and pass functions around as values.
  • Compose behavior with partial, comp and juxt.

defn anatomy

(defn greet
  "Returns a greeting string.            ; optional docstring
   Accepts an optional salutation."
  ([name]                                ; arity 1 delegates...
   (greet name "Hello"))
  ([name salutation]                     ; ...to arity 2
   (str salutation ", " name "!")))

(greet "Ada")               ;=> "Hello, Ada!"
(greet "Ada" "Bonjour")     ;=> "Bonjour, Ada!"
(doc greet)                 ; prints the docstring you wrote

The last expression's value is returned — there is no return keyword. Multi-arity dispatches on argument count (Kotlin default parameters solve a similar problem differently).

Variadic functions

(defn summarize
  "Summarizes any number of numbers."
  [label & xs]                    ; xs collects remaining args into a seq
  {:label label
   :count  (count xs)
   :total  (reduce + xs)})

(summarize "sales" 10 20 30)
;=> {:label "sales", :count 3, :total 60}

(apply summarize "bulk" [1 2 3])  ; spread a collection as args
;=> {:label "bulk", :count 3, :total 6}

Anonymous functions

;; full form - a first-class value like any other:
(fn [x] (* x x))

;; reader shorthand for short lambdas:
#(* % x)          ; wrong on purpose? no - see closure below
#(* % %)          ; % is arg 1, %1...%n beyond, %& = all rest

(map #(* % 2) [1 2 3])        ;=> (2 4 6)
(reduce #(+ %1 %2) 0 [1 2 3]) ;=> 6

;; rule of thumb: once nesting or multiple args appear,
;; prefer (fn [...]) or top-level defn - readability wins.

Closures: functions that remember

(defn adder [n]
  (fn [x] (+ x n)))       ; inner fn captures n from its birth environment

(def add-tax (adder 1.19))
(def add-shipping (adder 5))

(add-tax 100)      ;=> 119
(add-shipping 100) ;=> 105

;; factories replace whole design patterns:
(defn make-counter []           ; stateful - Module 07 makes this thread-safe
  (let [state (atom 0)]
    (fn [] (swap! state inc) @state)))
((make-counter)) ;=> 1
Coming from Java/Kotlin

Lambdas in Java capture effectively-final variables; Kotlin closures can mutate captured vars. A Clojure closure captures immutable bindings — so "remembering" is safe by construction. Where Java needs @FunctionalInterface, any Clojure function is already a JVM object implementing IFn (plus Runnable/Callable) — which is why (future (do-slow-work)) just works.

Destructuring: parameter unpacking done right

;; sequential destructuring
(let [[first-second-and :as all] [10 20 30 40]]
  [second all])
;=> [20 [10 20 30 40]]

(let [[a b & more] [1 2 3 4 5]]
  {:head b :rest more})
;=> {:head 2, :rest (3 4 5)}

;; map destructuring - the workhorse of API handlers:
(defn handle-create [{:keys [email roles] :or {roles #{:user}} :as payload}]
  {:status 201
   :body   {:email email :roles roles}})

(handle-create {:email "ada@x.io"})
;=> {:status 201, :body {:email "ada@x.io", :roles #{:user}}}

;; nested:
(defn city-of [{[street city] :address}]
  city)
(city-of {:address ["Main St" "London"]})   ;=> "London"

This is why Ring handlers take one map argument: the framework passes a request map and you destructure exactly what you need. Compare Spring's reflective argument resolvers doing the same thing invisibly.

Functions composing functions

;; sort-by takes a comparator or keyfn:
(sort-by :age [{:age 31} {:age 18} {:age 44}])
;=> ({:age 18} {:age 31} {:age 44})

(partial + 10)                 ; waits for the rest of the arguments
((partial + 10) 32)            ;=> 42

(comp clojure.string/upper-case clojure.string/trim)
((comp clojure.string/upper-case clojure.string/trim) "  hi ")
;=> "HI"                       ; right-to-left pipeline

(juxt :id :score)              ; returns a fn producing a vector of results
((juxt :id :score) {:id 7 :score 99})
;=> [7 99]

(complement empty?)            ;=> a negated predicate
(filter (complement nil?) [1 nil 2])   ;=> (1 2)
Named-argument calls, idiomatic style
(defn connect [{:keys [host port timeout] :or {port 8080 timeout 500}}]
  (str "connecting to " host ":" port))

(connect {:host "api.io"})

Instead of positional booleans like connect("api.io", true, false), Clojure APIs accept one options map — self-documenting call sites with safe defaults via :or.

Where this is used for real

Ring middleware is literally a function taking a handler and returning a new handler (Module 10); Reitit route handlers, re-frame event handlers and test fixtures are all plain functions passed by value. Master closures + destructuring and half of every Clojure library API becomes obvious.

Tasks

Task 1Clamp. Write (clamp lo hi x) returning x bounded into [lo, hi]. Use max/min.
Solution 
(defn clamp [lo hi x]
  (max lo (min hi x)))

(clamp 0 100 150)  ;=> 100
(clamp 0 100 -5)   ;=> 0
Task 2Average with defaults. Write (average numbers) using reduce and count; make it return nil for an empty input instead of dividing by zero (hint: (when (seq numbers) ...)).
Solution 
(defn average [numbers]
  (when (seq numbers)
    (/ (reduce + numbers) (count numbers))))

(average [2 4 9])  ;=> 5
(average [])       ;=> nil
Task 3Options-map function. Write (format-date {:keys [day month year] :or {month "01"}}) producing "year-month-day".
Solution 
(defn format-date [{:keys [day month year] :or {month "01"}}]
  (str year "-" month "-" day))

(format-date {:year 2024 :day 31})
;=> "2024-01-31"
Task 4Compose validation. Given predicates #(> (count %) 2) and #(clojure.string/includes? % "@"), build one predicate with every-pred and filter a list of candidate emails.
Solution 
(def valid-email?
  (every-pred #(> (count %) 2)
              #(clojure.string/includes? % "@")))

(filter valid-email? ["a@x.io" "@" "bob@corp.com"])
;=> ("a@x.io" "bob@corp.com")
;; every-pred / some-fn are ready-made combinators alongside comp/partial.
Task 5Closure factory. Write (multiplier table) returning a function that looks up rates in the given map and applies them: ((multiplier {:eur 1.08}) 100 :eur) → 108.0.
Solution 
(defn multiplier [rates]
  (fn [amount currency]
    (* amount (get rates currency))))

((multiplier {:eur 1.08 :gbp 1.27}) 100 :eur)
;=> 108.0
Summary · what you covered
  • defn anatomy: optional docstring, multi-arity bodies dispatch on argument count, and there is no return — the last expression is the value.
  • Variadic args: & xs collects the rest; apply spreads a collection into arguments.
  • Anonymous functions: (fn ...) and the #(...) shortening with %/%1, %2, %&.
  • Destructuring: sequential ([a b & rest]) and map ({:keys [..] :or {..}}) directly in the argument list.
  • Composition tools: partial, comp (right-to-left), juxt, apply, plus closures over enclosing bindings.
  • JVM citizenship: Clojure fns implement Runnable/Callable, so they drop straight into executors and SAM interfaces.

Exam · Module 04

1 · In the anonymous function #(+ %1 %2), what are %1 and %2?
In #(...) shorthand, %/%1 is the first arg, %2 the second, and %& gathers the rest.
2 · How does a multi-arity function choose which body runs?
Clojure functions dispatch on arity. Type-based polymorphism exists separately via protocols/multimethods (Module 08).
3 · What does (defn f [{:keys [a b] :or {b 2}}] [a b]) return for (f {:a 1})?
:or supplies defaults for absent keys, exactly like Kotlin's default parameter values.
4 · ((comp f g h) x) is equivalent to…
comp composes right-to-left: h runs first, its result feeds g, then f. If you want left-to-right pipelines, that is what threading macros do (Module 05).
5 · Why does (future (heavy-task)) work even though future expects a Runnable-like?
Clojure fns are objects implementing AFn/IFn plus Runnable and Callable, so they plug straight into executors, futures and Java APIs expecting SAM types.
