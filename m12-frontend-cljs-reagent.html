Frontend: ClojureScript + Reagent

Your React skills translate almost one-to-one: same model, but components return hiccup vectors and local state is an atom.

Goals

  • Write Reagent components: hiccup, form-1/2 components, controlled inputs.
  • Map every React hook you know to its Reagent/re-frame counterpart.
  • Consume your Module 10 backend and manage state at scale with re-frame.

What is ClojureScript?

ClojureScript is Clojure compiling to JavaScript instead of JVM bytecode — same language, same immutable collections, different runtime. The build tool you'll meet everywhere is shadow-cljs: first-class npm interop, fast incremental builds and hot reload.

;; shadow-cljs.edn
{:deps true
 :dev-http {8080 "public"}                       ; dev server + live reload
 :builds
 {:app {:target     :browser
        :output-dir "public/js"
        :asset-path "/js"
        :modules    {:main {:init-fn shop.ui/init}}
        :release    {:compiler-options {:optimizations :advanced}}}}}

Reagent = React, translated

(ns shop.ui
  (:require [reagent.core :as r]
            [react-dom/client :as rc]))

;; Form-1: pure props -> markup (like a function component)
(defn badge [{:keys [label color]}]
  [:span.badge {:style {:background color}} label])

;; Form-2: local state - closure over a reactive atom (like useState):
(defn counter []
  (let [count (r/atom 0)]                 ; created once per mounted instance
    (fn []                                 ; this inner fn re-renders
      [:button {:on-click #(swap! count inc)}
       "Clicked " @count " times"])))     ; deref = subscribe to changes

(defn init []
  (rc/render [counter]                     ; note: [component], not (component)
             (.getElementById js/document "root")))

A real component: todo list

(def todos (r/atom []))
(def draft (r/atom ""))

(defn add-todo []
  (when-not (clojure.string/blank? @draft)
    (swap! todos conj {:id (random-uuid) :label @draft :done false})
    (reset! draft "")))

(defn toggle [id]
  (swap! todos (fn [ts]
                 (mapv (fn [t] (if (= id (:id t)) (update t :done not) t))
                       ts))))

(defn todo-app []
  [:div
   [:input {:value @draft                                   ; controlled input
            :on-change #(reset! draft (.. % -target -value))
            :on-key-down #(when (= "Enter" (.-key %)) (add-todo))}]
   [:button {:on-click add-todo} "Add"]
   [:ul
    (for [{:keys [id label done]} @todos]
      ^{:key id}
      [:li {:class (when done "done")
            :on-click #(toggle id)}
       label])]])

Talking to your Module 10 API

(def items-state (r/atom {:status :loading}))

(defn fetch-items! []
  (reset! items-state {:status :loading})
  (-> (js/fetch "/api/items")
      (.then #(.json %))
      (.then (fn [json]
               (let [data (js->clj json :keywordize-keys true)]
                 (reset! items-state {:status :ready :items data}))))
      (.catch #(reset! items-state {:status :error :message (str %)}))))

(defn items-page []
  (r/with-let [_ (fetch-items!)]                  ; fetch once on mount
    (case (:status @items-state)
      :loading [:p "Loading..."]
      :error   [:p.error (:message @items-state)]
      :ready   [:ul
                (for [{:keys [id name]} (:items @items-state)]
                  ^{:key id} [:li name])])))

re-frame when the app grows

Plain atoms scale further than people expect. When many views share state and flows get complex, re-frame gives you the Redux-shaped discipline — unidirectional data flow around one central database:

(require '[re-frame.core :as rf])

;; the entire app state lives in ONE map (an atom under the hood):
(rf/reg-event-db                       ; event handler = pure transition
 ::add-item
 (fn [db [_ item]]
   (update db ::items conj item)))

(rf/reg-sub                            ; subscription = derived query
 ::items
 (fn [db _]
   (::items db)))

;; views dispatch events and subscribe to queries:
[:button {:on-click #(rf/dispatch [::add-item {:name "widget"}])}]

(let [items @(rf/subscribe [::items])]
  [:ul (for [{:keys [name]} items] ^{:key name} [:li name])])
  • Effects (HTTP, timers) are declared as data (:http-xhrio, custom fx) keeping handlers pure and testable.
  • Interceptors (middleware again!) handle logging, undo, validation.
  • Time-travel devtools included.
JS interop survival kit
(.-title obj)                      ; property access
(.log js/console "hi")             ; method call
(js->clj obj :keywordize-keys true) ; JS object -> Clojure map
(clj->js m)                        ; back again
#js {:onClick handlerFn}           ; raw JS object literal (for libs needing it)
(= 1 (js/parseInt "1"))            ; JS numbers are doubles - mind integer math

Rule of thumb: convert at the edges, live in maps inside your app.

Should you switch from React/TS?

ClojureScript shines when one team owns both ends: shared Malli schemas validate payloads identically front and back, and there is exactly one language semantics to reason about. TypeScript offers richer ecosystem hiring and editor inference. Many teams keep TS on huge consumer apps and use CLJS where full-stack coherence wins — internal tools, dashboards, startups shipping fast.

Where this is used for real

Figma's multiplayer engine runs ClojureScript compiled to JavaScript on their servers; Pitch built its presentation editor UI with Reagent; Roam Research is a full CLJS application. Nubank builds customer web experiences on the same stack.

Summary · what you covered
  • ClojureScript toolchain: shadow-cljs + npm with hot reload, dev server (:dev-http) and production builds via npx shadow-cljs release.
  • Hiccup instead of JSX: a component is a function returning a vector — tag keyword, optional attrs map, children; fragments and id/class sugar included.
  • Reagent component kinds: form-1 (pure props → markup), form-2 (returns a render fn, like useState local state with r/atom), and controlled inputs with ratoms.
  • Every React hook mapped: useState → form-2 + ratom; useEffect → :component-did-mount/lifecycle fns; useContext → Reagent context provider.
  • List keys: ^{:key id} metadata is exactly React’s key prop.
  • re-frame at scale: dispatch an event vector → pure handler updates app-db → memoized subscriptions notify views — Redux-style one-way flow, effects as data.

Exam · Module 12

1 · What does Reagent do that triggers a re-render?
Deref tracking replaces useState/useSelector wiring: @atom in render = dependency declaration.
2 · In hiccup, how do you render a link?
Vectors all the way down: tag keyword, attributes map, children.
3 · re-frame architecture most closely mirrors which React ecosystem pattern?
dispatch [event] -> pure handler updates app-db -> memoized subs notify views. Effects are data, interceptors are middleware.
4 · Why is ^{:key id} needed when rendering lists?
Identical concept to React's key prop, expressed as metadata on the hiccup vector.
5 · A famous production system written in ClojureScript running server-side belongs to…
Figma compiles its OT/multiplayer logic (ClojureScript) to JS and runs it on Node servers - one language across client and server logic.
