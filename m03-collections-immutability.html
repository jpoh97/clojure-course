Collections & Immutability

Vectors, lists, maps and sets with literal syntax everywhere — plus the persistent data structures that make immutability practical.

Goals
  • Master the four core collection types and their literals.
  • Use the essential map/vector operations from memory.
  • Understand structural sharing — why "copies" are cheap.
  • Exploit value equality and invokable keywords/maps.

The four core collections

[1 2 3]            ; vector - indexed, ordered. THE default collection
'(1 2 3)           ; list   - linked, ordered. Mostly for code/forms
{:name "Ada" :age 36}          ; map   - key -> value associations
#{:admin :member}               ; set   - unique values
TypeLiteralAdd withJava-ish equivalent
Vector[1 2 3](conj v x) at the endList.of(...) + random access
List'(1 2 3)(conj l x) at the frontLinkedList
Map{:a 1}(assoc m k v)Map.of(...)
Set#{1 2}(conj s x)Set.of(...)
Idiom

When you would reach for an ArrayList or a POJO/DTO in Java, you use a vector or map here. Lists are mainly how code itself is represented — that's why quoting (') suppresses evaluation of a literal list.

Vectors: your ArrayList replacement

(def langs ["clojure" "kotlin" "java"])

(nth langs 0)        ;=> "clojure"
(langs 1)            ;=> "kotlin"     vectors are invokable!
(get langs 9 :none)  ;=> :none        safe access with default
(conj langs "scala") ;=> ["clojure" "kotlin" "java" "scala"]  NEW vector
langs                ;=> ["clojure" "kotlin" "java"]          original intact
(count langs)        ;=> 3
(vec (range 3))      ;=> [0 1 2]     build from anything seqable

Maps: your DTO/POJO/JSONObject replacement

(def user {:name "Ada" :roles #{:admin} :address {:city "London"}})

(get user :name)                 ;=> "Ada"
(:name user)                     ;=> "Ada"   keywords are functions!
(user :name)                     ;=> "Ada"   maps are functions too!
(get-in user [:address :city])   ;=> "London"
(get-in user [:address :zip] "-") ;=> "-"    nested lookup w/ default

(assoc user :premium true)       ; add / overwrite key
(dissoc user :roles)             ; remove key
(update user :name clojure.string/upper-case)  ; transform a value
(assoc-in user [:address :zip] "E1")
(update-in user [:roles] conj :editor)

(select-keys user [:name :age])
(keys user)  (vals user)
(contains? user :name)           ;=> true
(count user)                     ;=> 3

(def defaults {:retries 3 :timeout 100})
(merge defaults {:timeout 500})  ;=> {:retries 3, :timeout 500}
(merge-with + {:a 1} {:a 2})     ;=> {:a 3}
Coming from Java/Kotlin

A Clojure map plays the roles of DTO + Builder + Bean Validation target all at once. Where Kotlin gives you data class User(copy = ...), Clojure gives you assoc/update on plain maps. There is no Lombok because there are no classes to write — and when you truly need a typed thing, Module 08 introduces defrecord.

Sets and clojure.set

(def roles #{:admin :editor})
(contains? roles :admin)     ;=> true   ; O(1)-ish membership
(conj roles :viewer)
(disj roles :admin)
(require '[clojure.set :as set])
(set/union #{1 2} #{2 3})            ;=> #{1 2 3}
(set/intersection #{1 2} #{2 3})     ;=> #{2}
(set/difference  #{1 2 3} #{2})      ;=> #{1 3}

(distinct [1 1 2 3 3])       ;=> (1 2 3)  dedupe any sequence
(frequencies "banana")       ; char counts - surprisingly useful

Immutability that doesn't cost a fortune

All four structures are persistent: every "modification" returns a new value while internally sharing structure with the old one. Adding to a billion-element vector copies O(log32 n) nodes — effectively a handful of pointers:

(def xs (vec (range 1000000000)))   ; a billion ints... instantly
(def ys (conj xs :end))             ; "copies" xs in microseconds
(nth ys 999999999)                  ;=> 999999999  still readable, fast

This is what lets Clojure treat state as values over time: pass a map anywhere, store it, share it across threads — nobody can corrupt it behind your back. Compare the defensive copying, unmodifiable wrappers and concurrent-modification exceptions you manage in Java.

Value equality unlocks clean modeling

(= {:a 1} {:a 1})                    ;=> true regardless of construction path
(= #{"x"} (set ["x" "x"]))           ;=> true

;; maps as keys - painless composite keys:
(def price-table {{:from :usd :to :eur} 0.92
                  {:from :eur :to :gbp} 0.85})
(price-table {:from :usd :to :eur})  ;=> 0.92
Performance note

Small maps (up to 8 entries) are array-backed array-maps with linear scan — faster than hashing. Large maps become hash-array-mapped tries automatically. You rarely choose; the runtime does. For sorted needs there are sorted-map / sorted-set-by.

EDN: data as a file format

The literal syntax you just learned doubles as a serialization format — Extensible Data Notation. Config files, route tables and system definitions ship as EDN; #inst "2024-01-01" style tagged literals extend it. Think JSON with keywords, sets, richer types and no ambiguity about nil vs missing.

{:port 3000
 :db   {:host "localhost" :port 5432 :dbname "shop"}
 :features #{:search :export}}
Where this is used for real

Every Ring request/response, Reitit route match, Malli schema and HoneySQL query in Modules 10–11 is exactly these data structures. Nubank publicly credits immutable data + explicit transformations as a pillar of their ability to refactor financial services safely.

Tasks

Task 1User profile surgery. Given (def u {:email "ada@x.io" :roles #{:user}}): change the email, add role :admin, and produce {"ada@x.io" #{:user :admin}}-style output keyed by email.
Solution 
(-> u
    (assoc :email "ada@new.io")
    (update :roles conj :admin))
;=> {:email "ada@new.io", :roles #{:user :admin}}

{(u :email) (u :roles)}
;=> {"ada@x.io" #{:user}}
Task 2Safe deep lookup. From (def order {:customer {:address {:city "Berlin"}}}) fetch :city; then fetch :zip returning "n/a" when absent.
Solution 
(get-in order [:customer :address :city])        ;=> "Berlin"
(get-in order [:customer :address :zip] "n/a")   ;=> "n/a"
Task 3Merge configs. Combine {:db {:port 5432}} with {:db {:host "db.local"}} so both keys survive (merge alone replaces the inner map!).
Solution 
(merge-with merge {:db {:port 5432}} {:db {:host "db.local"}})
;=> {:db {:port 5432, :host "db.local"}}
Task 4Cart math preview. Given items [{:price 10} {:price 25} {:price 5}], compute the total using map and reduce (both get full treatment soon — copy-paste courage).
Solution 
(reduce + (map :price [{:price 10} {:price 25} {:price 5}]))
;=> 40
Task 5Prove cheap copies. Create a 1M-element vector, time conj onto it with (time ...), then confirm the original kept its old count.
Solution 
(def big (vec (range 1000000)))
(time (def big2 (conj big :x)))
;"Elapsed time: ~0.05 msecs"
[(count big) (count big2)]   ;=> [1000000 1000001]
Summary · what you covered
  • Four core types & literals: vector [1 2 3], list ’(1 2 3), map {:a 1}, set #{1 2} — the default is the literal.
  • Essential ops: conj, assoc, dissoc, get/nth, keys/vals, contains?, count, seq.
  • Immutability is practical: persistent structures use structural sharing — new versions are cheap and readers of the old one see an unchanged world.
  • Value equality: maps/collections compare by content, so they work as keys and make tests read like truth tables.
  • Everything is invokable: keywords/maps/sets/vectors act as functions (lookup, membership, lookup-by-index).

Exam · Module 03

1 · Which collection has no literal syntax?
Vectors [], lists (), maps {} and sets #{} all have literals. Arrays are low-level JVM interop territory (Module 08).
2 · What does (conj [1 2] 3) return?
conj adds at the natural end of a vector and returns a new value. (On a list, the "natural end" is the front.)
3 · Why are persistent collections "cheap to copy"?
Structural sharing means only O(log32 n) new nodes are allocated per update; readers of the old version see an unchanged world.
4 · What is (:email {:email "a@b.c"})?
Keywords, symbols, maps, sets and vectors are all invokable - a small polymorphism superpower of Clojure syntax.
5 · What is (= {:a 1 :b 2} (assoc {:a 1} :b 2))?
Maps compare by their entries. This value-equality is why maps work as map keys and make tests read like truth tables.
