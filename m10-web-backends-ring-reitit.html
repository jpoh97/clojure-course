Web Backends: Ring + Reitit

The Clojure equivalent of Spring MVC — except handlers are plain maps-in/maps-out functions you can test in the REPL.

Goals
  • Understand the Ring spec: request/response as data, middleware as functions.
  • Build a real JSON API with routing, validation and error handling.
  • Test handlers directly in the REPL without booting a server.
  • Package and deploy like any JVM service.

The Ring model: HTTP as data

Ring defines three things: handlers (maps in, maps out), middleware (functions that decorate handlers) and adapters (Jetty/Undertow/http-kit glue to sockets). That's the whole framework:

;; A handler receives a request MAP and returns a response MAP.
(defn handler [request]
  {:status 200
   :headers {"Content-Type" "text/plain"}
   :body "hello"})

;; What's inside a request map? Everything the server saw:
{:request-method  :get
 :uri             "/api/users/42"
 :query-string    "active=true"
 :headers         {"accept" "application/json"}
 :server-port     80
 :body            #object[...]           ; raw InputStream
 ;; added by middleware later:
 :path-params     {:id "42"}
 :params          {"active" "true"}
 :body-params     {:email "ada@x.io"}}

A real JSON API

(ns shop.api
  (:require [ring.adapter.jetty :as jetty]
            [reitit.ring :as ring]
            [reitit.ring.middleware.muuntaja :as muuntaja-mw]
            [reitit.ring.middleware.parameters :as parameters]
            [reitit.ring.coercion :as coercion]
            [muuntaja.core :as m]))

;; ---- handlers: pure functions --------------------------------------
(defn health [_]
  {:status 200 :body {:status "up"}})

(defn hello [{:keys [path-params]}]
  {:status 200 :body {:message (str "Hello, " (:name path-params))}})

(defn list-items [{:keys [query-params]}]          ; ?q=...&limit=...
  (let [q     (get query-params :q)
        limit (parse-long (get query-params :limit "20"))]
    {:status 200 :body {:query q :limit limit :items []}}))

(defn create-item [{:keys [body-params]}]
  {:status 201
   :body (assoc body-params :id (str (random-uuid)))})

;; ---- routing: data, not annotations ---------------------------------
(def app
  (ring/ring-handler
    (ring/router
      [["/api"
        {:middleware [parameters/parameters-middleware       ; parse query/form
                      muuntaja-mw/format-middleware          ; negotiate JSON/EDN
                      coercion/coerce-request-middleware     ; validate input
                      coercion/coerce-response-middleware]}  ; validate output
        ["/health"      {:get health}]
        ["/hello/:name" {:get hello
                         :parameters {:path {:name string?}}}]
        ["/items"
         [""     {:get  list-items
                  :post {:handler    create-item
                         :parameters {:body [:map
                                             [:name  string?]
                                             [:price number?]]}}}]]]]

      {:data {:muuntaja m/instance}})
    (ring/create-default-handler)))                ; 404/405/406 defaults

(defn -main []
  (jetty/run-jetty app {:port 3000 :join? false}))

Testing handlers in the REPL - no container, no mock MVC

user=> (require '[shop.api :as api])
user=> (api/app {:request-method :get :uri "/api/hello/ada"})
;=> {:status 200, :body {:message "Hello, ada"}}

user=> (api/app {:request-method :post
                 :uri "/api/items"
                 :body-params {:name "widget" :price 9.99}})
;=> {:status 201, :body {:name "widget", :price 9.99, :id "..."}}

user=> (api/app {:request-method :post
                 :uri "/api/items"
                 :body-params {:name "" :price "free"}})
;=> 400 with a Malli explanation of exactly which field failed
Why this matters

This is the payoff of everything-as-data: your entire API is testable as ordinary function calls. Integration tests become (is (= 200 (:status (app req)))) — milliseconds instead of @SpringBootTest context boots.

Middleware: filters as higher-order functions

;; a middleware takes a handler, returns a decorated handler:
(defn wrap-timing [handler]
  (fn [req]
    (let [t0  (System/nanoTime)
          res (handler req)]
      (println (:request-method req) (:uri req)
               (-> (- (System/nanoTime) t0) (/ 1e6) long) "ms")
      res)))

(defn wrap-errors [handler]
  (fn [req]
    (try
      (handler req)
      (catch Exception e
        (let [{:keys [code]} (ex-data e)]
          {:status (or code 500)
           :body   {:error (.getMessage e)}})))))

(defn wrap-auth [handler]
  (fn [req]
    (if (= "Bearer secret-token" (get-in req [:headers "authorization"]))
      (handler req)
      {:status 401 :body {:error "unauthorized"}})))

(def app (wrap-timing (wrap-errors app)))   ; compose explicitly

Order composes visibly — no annotation scanning surprises. Community middlewares cover CORS, cookies, sessions, multipart, static resources and JWT verification (buddy-auth, ring-jwt).

    (ring/router [["/api/orders" {:get #(list-orders % ds)}]])))

Nubank runs hundreds of production Clojure services on precisely this stack family (Ring-compatible, Datomic/Postgres storage). CircleCI built its original platform with these libraries. For CRUD-plus-rules APIs, a working validated endpoint is ~30 lines total — and every line is inspectable data.

Tasks

Task 1Echo endpoint. Add POST /api/echo that validates a body of [:map [:message string?]] and returns the message uppercased with status 201. Test it in the REPL before starting Jetty.
Solution 
(defn echo [{:keys [body-params]}]
  {:status 201
   :body   {:echo (clojure.string/upper-case (:message body-params))}})

;; route:
["/echo" {:post {:handler    echo
                 :parameters {:body [:map [:message string?]]}}}]
Task 2Request-ID middleware. Write wrap-request-id that puts a UUID into the request under :req-id, echoes it back in the response header X-Request-Id.
Solution 
(defn wrap-request-id [handler]
  (fn [req]
    (let [id (str (random-uuid))
          res (handler (assoc req :req-id id))]
      (assoc-in res [:headers "X-Request-Id"] id))))
Task 3In-memory store. Hold items in an atom (Module 07); implement GET by id returning 200 or 404.
Solution 
(defonce db (atom {}))

(defn get-item [{{:keys [id]} :path-params}]
  (if-some [item (get @db id)]
    {:status 200 :body item}
    {:status 404 :body {:error "not found"}}))
Task 4Custom 404. Replace the default handler so unknown routes return JSON {:error "no such route"}. (Hint: create-default-handler accepts :not-found.)
Solution 
(def not-found
  (fn [_] {:status 404 :body {:error "no such route"}}))

(ring/create-default-handler
  {:not-found (fn [_]
                {:status 404
                 :headers {"Content-Type" "application/json"}
                 :body "{\"error\":\"no such route\"}"})})
;; default-handler bodies are strings/bytes - hence the raw JSON.

Exam · Module 10

1 · In Ring, a handler is…
Request in (map), response out ({:status :headers :body}). No interfaces, no reflection magic.
2 · Ring middleware is…
((wrap-timing wrap-errors app)) - decoration is explicit composition you control and can unit-test standalone.
3 · With Reitit + Malli coercion, where does a validated request body arrive?
Muuntaja decodes content negotiation into :body-params; Malli validates per the route's :parameters and rejects bad requests with details before your handler runs.
4 · Why can you test handlers in the REPL with plain maps?
The adapter (Jetty) is just one caller of your handler. Any other caller - tests, the REPL, other middleware - works identically.
5 · Which template gives you a full-stack starter similar to Spring Initializr?
Luminus/Kit scaffold web + DB + frontend profiles. Pedestal suits interceptor-style high-throughput services.
