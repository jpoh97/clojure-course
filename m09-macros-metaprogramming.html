Macros & Metaprogramming

Because code is data, you can write code that writes code — extending the language itself. Used sparingly, it removes boilerplate forever.

Goals
  • Understand the reader → macroexpansion → evaluation pipeline.
  • Master syntax-quote, unquote, splice and auto-gensym.
  • Write safe, useful macros and debug them with macroexpand-1.
  • Know when a plain function is the better answer (usually).

Code is data

The same structures you learned in Module 03 represent source code. Quoting turns off evaluation:

(+ 1 2)          ;=> 3            evaluate: a call
'( + 1 2)        ;=> (+ 1 2)      quoted:   a list containing symbols
(first '(+ 1 2)) ;=> +
(eval '(+ 1 2))  ;=> 3            evaluation is just a function over data!

A macro is a function that runs at compile time. It receives its arguments unevaluated (as forms) and must return a form to be compiled in their place:

(defmacro my-first [coll]
  (first coll))

(my-first (+ 1 2))     ; the macro receives the FORM (+ 1 2),
                       ; calls plain (first ...) on it at COMPILE TIME,
                       ; and returns the symbol + - so this expression
                       ; expands to just: +
(my-first (+ 1 2))     ;=> #object[clojure.core$_PLUS_] ...the function!
;; silly example - but notice: we computed WITH code, before any runtime.

Syntax-quote: templating done right

`(if ~test ~else ~then)
;; `  syntax-quote: template; fully qualifies symbols (hygiene!)
;; ~  unquote: insert runtime values here
;; ~@ unquote-splicing: splice a LIST into place

(defmacro unless [test & body]
  `(when-not ~test ~@body))

(unless false (println "runs") :done)     ;=> prints, returns :done

(macroexpand-1 '(unless false :ok))
;=> (clojure.core/when-not false :ok)     ; inspect what your macro builds

The canonical bug: multiple evaluation

;; naive or - evaluates `a` twice!
(defmacro bad-or [a b]
  `(if ~a ~a ~b))
(bad-or (do (println "side effect!") true) false)   ; prints twice!

;; fix: bind once with an auto-gensym (x# becomes unique per expansion):
(defmacro my-or [a b]
  `(let [x# ~a] (if x# x# ~b)))
Macro rules of engagement

1) Evaluate each argument-form exactly once — bind to gensyms.
2) Never capture caller variables — use x#/gensym.
3) Write the function first. Only make it a macro if you genuinely need unevaluated forms, custom control flow, or compile-time generation.

Useful macros you might actually ship

;; 1. tracing helper for development:
(defmacro deftrace [name args & body]
  `(defn ~name ~args
     (let [result# (do ~@body)]
       (println ~(str name) ~args "=>" result#)
       result#)))

(deftrace add [a b] (+ a b))
(add 2 3)                    ; prints "add [2 3] => 5", returns 5

;; 2. retry logic as control flow:
(defmacro with-retries [n & body]
  `(loop [tries# ~n]
     (or (try ~body (catch Exception _# nil))
         (when (pos? tries#)
           (Thread/sleep 100)
           (recur (dec tries#))))))

(with-retries 3 (flaky-api-call))

;; 3. resource management DSL (this IS how with-open works):
(defmacro with-resource [[bind open close] & body]
  `(let [~bind ~open]
     (try ~@body (finally (~close ~bind)))))
Coming from Java/Kotlin

What requires annotation processors, compiler plugins, bytecode weaving or Lombok in the JVM mainstream, Clojure does with ordinary functions over code. deftest, ->, with-open, lazy-seq are all library-grade macros — there is no special "framework magic" layer between you and the language.

Security note

Never call (eval (read-string user-input)) on untrusted input — that is remote code execution by design. Data should travel as EDN/JSON parsed into maps, never as executable forms.

Where this is used for real

You will mostly use macros rather than write them: routing tables, schema definitions, test frameworks and async code all read like little DSLs thanks to macros. Writing them is reserved for killing repeated boilerplate — exactly the niche Lombok/codegen occupies elsewhere.

Tasks

Task 1my-when. Implement (my-when test & body) using only if inside your macro.
Solution 
(defmacro my-when [test & body]
  `(if ~test (do ~@body) nil))

(macroexpand-1 '(my-when true (prn 1) 42))
;=> (clojure.core/if true (do (prn 1) 42) nil)
Task 2Infix calculator macro. Make (math 3 + 4) work by rearranging forms at compile time.
Solution 
(defmacro math [left op right]
  `(~op ~left ~right))

(math 3 + 4)      ;=> 7
(math 10 < 99)    ;=> true
Task 3Benchmark macro. Write (bench expr) returning both the elapsed milliseconds and the result.
Solution 
(defmacro bench [expr]
  `(let [start# (System/nanoTime)
         val#   ~expr]
     {:result  val#
      :elapsed (/ (- (System/nanoTime) start#) 1e6)}))

(bench (reduce + (range 1000000)))
;=> {:result 499999500000, :elapsed 12.34}
Task 4Hunt the double-eval. Fix (defmacro twice [e] `(do ~e ~e)) so side effects run once.
Solution 
(defmacro once-but-return-twice [e]
  `(let [v# ~e] [v# v#]))
;; general principle: bind every argument-form to a gensym before reuse.

Summary · what you covered
  • Code is data: quoting (’(+ 1 2)) yields a list; eval makes evaluation just a function over that data.
  • The pipeline: reader → macroexpansion → compile → evaluate; a macro receives forms unevaluated and returns a replacement form.
  • Template toolkit: ` syntax-quote (auto-qualifies), ~ unquote, ~@ unquote-splicing, x# auto-gensym for hygiene.
  • Debugging: macroexpand-1/macroexpand-all, and the canonical “multiple evaluation” bug that fresh macros fall into.
  • Judgment: write a function first; reach for a macro only when you need unevaluated forms, custom control flow, or compile-time transformation (as ->/deftest themselves do).

Exam · Module 09

1 · When do macros run?
A macro call is replaced by whatever form the macro returns; the runtime only ever sees the expansion.
2 · What does ~ do inside a syntax-quote?
` templates (with qualified symbols); ~ switches back to normal evaluation for one sub-form; ~@ splices lists.
3 · Why use x# instead of x in macro templates?
Auto-gensyms prevent your internal names from colliding with names the caller uses - a classic macro hygiene bug.
4 · Which tool shows what a macro call expands into?
macroexpand-1 performs one expansion step - essential for debugging your own and understanding others' macros.
5 · What's the community rule of thumb about writing macros?
Functions compose, pass as values and test trivially. Macros are for syntactic abstraction - powerful but costlier to reason about.
