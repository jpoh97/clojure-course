Setup & the REPL

Get the toolchain running and adopt the workflow that makes Clojure development feel different from everything else on the JVM.

Goals
  • Install the JDK and Clojure CLI (and know when to reach for Leiningen).
  • Create and run a minimal project.
  • Use the REPL for exploration and self-documentation.
  • Set up an editor with an integrated REPL (Calva or Cursive).

What you will install

What you will install

Clojure is a library on the JVM: the compiler is a jar that your programs depend on. You need three things:

  1. A JDK — any modern one works. Temurin 21 LTS is a safe default.
  2. A build runner — either the official Clojure CLI (clj, driven by deps.edn) or Leiningen (lein). Both download dependencies from Maven Central, exactly like Gradle/Maven do.
  3. An editor with REPL integration — VS Code + Calva, or IntelliJ + Cursive (the natural pick coming from JetBrains world).
# Windows (PowerShell) - adjust for macOS/Linux as documented on clojure.org
winget install EclipseAdoptium.Temurin.21.JDK
winget install Clojure.ClojureCLI        # official CLI tools
# alternative: scoop install temurin21-jdk; scoop install clojure

java -version                            # should print 21.x
clj --version                            # should print a Clojure version like 1.12.x
Coming from Java/Kotlin

deps.edn is to the Clojure CLI what build.gradle is to Gradle: an EDN (Extensible Data Notation — think JSON with keywords) file declaring paths and dependencies. Leiningen plays the same role with project.clj plus extra conveniences (templates, packaging). Older tutorials use Leiningen; new projects usually prefer the CLI. This course uses the CLI.

Your first project

Create a folder with this structure:

hello/
  deps.edn
  src/hello/core.clj
;; deps.edn
{:paths ["src"]
 :deps {org.clojure/clojure {:mvn/version "1.12.1"}}}
;; src/hello/core.clj
(ns hello.core)

(defn -main []
  (println "Hello from Clojure!"))
cd hello
clj -M -m hello.core          # compiles and calls hello.core/-main
Hello from Clojure!

The REPL: your new home screen

Run clj with no arguments to get a REPL — Read, Evaluate, Print, Loop. Unlike jshell, this is not a debugging toy: production Clojure developers spend most of the day connected to a REPL attached to their real application.

$ clj
Clojure 1.12.1
user=> (+ 1 2 3)
6
user=> (def name "Ada")
#'user/name
user=> (str "Hi, " name)
"Hi, Ada"
user=> *1                       ; *1 holds the last printed result
"Hi, Ada"
user=> (* 2 21)

The REPL can describe itself:

user=> (doc map)                ; prints docstring and signature
user=> (source take)             ; shows the actual implementation!
user=> (apropos "filter")        ; find functions by substring
user=> (dir clojure.string)      ; list everything in a namespace
user=> (require '[clojure.string :as str])   ; load a lib, alias it
user=> (str/upper-case "quiet")
"QUIET"
The core workflow shift

In Spring you write a controller, restart, curl, read logs, repeat. In Clojure you connect the REPL to your app, evaluate a single handler function with a hand-made request map, inspect the response map instantly, tweak the function, re-evaluate — seconds, not minutes. Modules 07–11 lean on this constantly.

Reloading code without restarting

When files change on disk, reload namespaces into the running process with tools.namespace. Add it as a dev dependency:

;; deps.edn (aliases section)
{:paths ["src"]
 :deps {org.clojure/clojure {:mvn/version "1.12.1"}}
 :aliases
 {:dev {:extra-deps {org.clojure/tools.namespace {:mvn/version "1.5.0"}}}}}
;; in the REPL (started with clj -A:dev or from your editor)
(require '[clojure.tools.namespace.repl :refer [refresh]])
(refresh)                        ; clean re-load of changed namespaces

Later, systems built with Integrant get a one-call (reset) that stops and restarts the whole application in-process — faster than Spring DevTools hot-restarts.

Where this is used for real

Teams script operational chores with Babashka (bb) — a native compiled Clojure interpreter that starts in milliseconds:

winget install babashka.cli       # or scoop install babashka
#!/usr/bin/env bb
;; deploy-notes.bb - instant-startup scripting, replaces bash+curl glue
(println (slurp "https://api.github.com/repos/clojure/clojure/tags"))

Tasks

Task 1Verify your toolchain. Print the output of java -version and clj --version. If clj fails on Windows PowerShell, confirm the installer added its scripts to PATH.
Task 2First REPL session. Start clj, compute (* 6 7), bind the result with def, then call (str "answer: " answer-var).
Solution 
user=> (def answer (* 6 7))
#'user/answer
user=> (str "answer: " answer)
"answer: 42"
Task 3Explore the docs. Look up (doc reduce), (source take) and find every function whose name mentions "take".
Solution 
(doc reduce)
(source take)
(apropos "take")     ; => (take take-last take-nth take-while)
Task 4Scratchpad habit. Add a (comment ...) block to core.clj, put an expression inside, and evaluate it from your editor without touching the main code.
Solution 
(ns hello.core)

(defn -main [] (println "Hello from Clojure!"))

(comment
  (+ 40 2)                 ; place cursor here, press Alt+Enter (Calva)
  (str "scratch" " pad"))
Summary · what you covered
  • Three moving parts: a JDK (Temurin 21), the Clojure CLI (clj, driven by deps.edn) or Leiningen, and an editor with REPL integration (VS Code + Calva / IntelliJ + Cursive).
  • Minimal project shape: deps.edn declaring paths + Maven deps, and a src/<ns>/core.clj with a defn -main, run via clj -M -m.
  • REPL-driven workflow: evaluate forms into your live app; inspect and re-evaluate in seconds instead of restart → curl → logs.
  • Self-documentation: doc, source, apropos, dir; *1/*2/*3 recall results and *e the last exception.
  • Scratchpads: (comment ...) lets you experiment inside a file without executing its contents as a program.

Exam · Module 01

1 · What does REPL stand for?
The REPL reads a form, evaluates it, prints the result, and loops. It is the primary interactive development environment for Clojure.
2 · Which tool reads a deps.edn file?
Leiningen uses project.clj; the official CLI tools use deps.edn. Both resolve libraries from Maven Central.
3 · Inside a REPL session, what does *1 hold?
*1, *2 and *3 hold the last three printed results; *e holds the last exception.
4 · Which editor setups give you an integrated REPL against your running program?
All major editors support connected REPL workflows: evaluating individual forms from source files into the live process.
5 · What does the (comment ...) form do?
(comment) returns nil and never runs its body, yet editors can still evaluate expressions inside it selectively - ideal for experiments.
