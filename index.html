Why does Clojure exist — and why do teams choose it?

Clojure is a modern Lisp that compiles to JVM bytecode. It gives you the performance, libraries and deployment story of Java, combined with functional programming, immutable data structures and an interactive REPL workflow.

JVM

The whole Java world, for free

Call Jackson, Netty, Kafka, the AWS SDK, HikariCP — any of the millions of Maven artifacts — directly from Clojure. Deploys like any Spring app: a jar on the JVM.

{}

Immutable data by default

Vectors, maps and sets are persistent and safely shareable across threads. Entire bug categories you fight in concurrent Java/Kotlin code simply disappear.

>_

REPL-driven development

Evaluate code inside your running application. No redeploy cycle to try an idea — think jshell/kotlin REPL, but central to how production systems are actually built.

( )

A language you can extend

Code is data (Lisp). Macros let libraries provide what other ecosystems need framework features for. The language stays small; the library ecosystem does the rest.

≈100

Small core, huge leverage

Roughly a hundred core functions compose into everything: HTTP handlers are just maps-in/ map-out functions, SQL queries are just data structures. Less ceremony than layered frameworks.

$

Battle-tested at serious scale

Nubank serves tens of millions of customers on Clojure microservices and liked it so much they bought the company behind it (Cognitect) in 2020.

The one-paragraph pitch

In Spring, behavior lives in classes annotated with framework magic, and state mutates all over the place. In Clojure, behavior is plain functions and state is plain immutable data — so you test functions directly in the REPL instead of booting a container, and you reason about your program like data transformations instead of object interactions.

;; Modeling data: Java vs Clojure
;; Java:   Map<String,Object> user = new HashMap<>(); user.put("email", "ada@x.io");
;; Kotlin: val user = mapOf("email" to "ada@x.io")

(def user {:email "ada@x.io" :roles #{:admin}})     ; a value - just data

(assoc user :name "Ada")                            ; "change" returns a NEW value
user                                                ; original untouched
=> {:email "ada@x.io", :roles #{:admin}}

What is Clojure actually used for?

Its sweet spot is server-side systems where correctness under concurrency and fast iteration matter.

API

Web APIs & services

Best fit. Ring + Reitit + next.jdbc against Postgres. Handlers are pure functions — trivially testable without booting Spring.

FIN

Fintech & banking

Nubank's choice. Immutability plus STM/atoms make money-moving invariants easier to prove and harder to corrupt.

ETL

Data processing & pipelines

Lazy sequences, transducers and reducers shine at transforming streams of records; great fit with Kafka via its native Java client.

WEB

Full-stack SaaS

ClojureScript + Reagent/re-frame on the frontend shares schemas and validation code with your backend — one language, both ends.

OPS

Tooling & scripting

Babashka starts instantly and replaces Bash/Python glue scripts with a real language on the JVM.

DB

Immutable-database products

Datomic, XTDB and Datahike were born here — databases built on the same immutable-values philosophy as the language.

The roadmap

Thirteen modules in three phases. Each module = short lecture + tasks with solutions + a graded exam (70% to pass). Progress is saved in your browser.

PHASE 1

Foundations

Get productive in the REPL and learn to read and write idiomatic Clojure.

  • M01Setup & the REPL — install the toolchain, editors (Calva/Cursive), REPL-driven workflow
  • M02Syntax Essentials — expressions, scalars, keywords, namespaces, truthiness
  • M03Collections & Immutability — vectors, maps, sets, persistent data structures
  • M04Functions & Closures — arities, varargs, destructuring, higher-order functions
  • M05Control Flow & Threading Macros — cond/case, loop/recur, exceptions, -> and ->>
PHASE 2

Idiomatic Power

The features that make Clojure feel like Clojure — and make it safe at scale.

  • M06Sequences, Laziness & Transducers — the seq abstraction vs Java Streams
  • M07State & Concurrency — atoms, refs & STM, agents, core.async
  • M08Java Interop for JVM Veterans — call anything, defrecord/defprotocol, type hints
  • M09Macros & Metaprogramming — syntax-quote, writing your own control flow
PHASE 3

Real Applications

Everything you need to ship a production system — ending with a full-stack capstone.

  • M10Web Backends: Ring + Reitit — middleware, JSON, Malli validation, error handling, deploy
  • M11PostgreSQL: next.jdbc + HoneySQL — pools, transactions, migrations, JSONB
  • M12Frontend: ClojureScript + Reagent — your React skills, translated; re-frame state management
  • M13Testing & Capstone Project — clojure.test, test.check, clj-kondo + full-stack project spec

How this site works

  • Lectures are short and code-heavy, with constant comparisons to Spring, Kotlin and React concepts you already know.
  • Tasks after each lecture are small REPL exercises; most have expandable solutions.
  • Exams are 5-question quizzes. Score 70%+ to mark the module complete — checkmarks appear in the sidebar and your progress persists locally.
  • Pace: roughly one module per day gets you through in two weeks. Modules 10–12 assume 01–09 but are readable earlier if you want the payoff first.
  • Prerequisites: JDK 21 (Temurin), VS Code + Calva or IntelliJ + Cursive, Docker for the Postgres module.
Honest tradeoffs before you invest

Dynamic typing means fewer compile-time guarantees than Kotlin — the ecosystem compensates with Malli/spec schemas, REPL-driven tests and clj-kondo static analysis (all covered). Cold-start time makes Clojure a poor fit for CLI-heavy tooling unless you use Babashka or GraalVM. Error messages and stack traces take getting used to. And yes, parentheses — editors handle them, and by Module 03 you stop seeing them.
