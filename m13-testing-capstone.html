Testing & Capstone Project

Tests are the safety net that makes a dynamic language feel safe — then you prove everything by shipping LinkVault.

Goals
  • Test units and HTTP handlers with clojure.test.
  • Generate edge cases with test.check property-based tests.
  • Add linting/formatting/CI so refactors stay fearless.
  • Build the full-stack capstone using every module.

clojure.test essentials

(ns shop.domain-test
  (:require [clojure.test :refer [deftest is testing are]]
            [shop.domain :as d]))

(deftest discount-rules
  (testing "premium members get 10% off orders over 100"
    (is (= 90.0 (d/discount {:tier :premium :total 100}))))
  (testing "everyone else pays full price"
    (is (= 100 (d/discount {:tier :free :total 100})))))

;; table-style assertions with `are`:
(deftest grades
  (are [score expected] (= expected (d/grade score))
    95 :A   80 :B   61 :C   10 :F))

Because functions are values and state is explicit, there is rarely anything to mock: construct inputs as maps, assert outputs as maps. Fixtures cover setup:

(use-fixtures :each                     ; like @BeforeEach
  (fn [t] (reset! db/test-state {}) (t)))

(use-fixtures :once                     ; like @BeforeAll - start container once
  (fn [t] (db/start!) (t) (db/stop!)))

HTTP integration tests without booting Spring

(ns shop.api-test
  (:require [clojure.test :refer [deftest is]]
            [ring.mock.request :as mock]
            [shop.api :as api]))

(deftest health-endpoint
  (let [{:keys [status body]} (api/app (mock/request :get "/api/health"))]
    (is (= 200 status))
    (is (= {:status "up"} body))))

(deftest create-validates-body
  (let [req      (-> (mock/request :post "/api/items")
                     (mock/json-body {:name "" :price "free"}))
        response (api/app req)]
    (is (= 400 (:status response)))))     ; Malli rejection - no server started

Property-based testing with test.check

Like jqwik/Kotest properties: describe an invariant for all generated inputs; when it fails, the framework shrinks toward the minimal counterexample.

(require '[clojure.test.check.properties :as prop]
         '[clojure.test.check.clojure-test :refer [defspec]]
         '[clojure.test.check.generators :as gen])

;; serialization must round-trip for ANY payload:
(defspec json-roundtrip 200
  (prop/for-all [m (gen/map gen/keyword
                            (gen/one-of [gen/int gen/string gen/boolean]))]
    (= m (cheshire.core/parse-string
           (cheshire.core/generate-string m) true))))

;; classic invariant:
(defspec reverse-twice 100
  (prop/for-all [v (gen/vector gen/small-integer)]
    (= v (vec (reverse (reverse v))))))
Where properties pay off most

Parsers, serializers, pagination math, money rounding, permission logic — anywhere examples lie. A generator found a real bug in my own code once because an empty-string header case was never in any hand-written example.

Database tests

  • Rollback pattern: open a connection, begin tx per test, roll back at the end — zero cleanup.
  • Dedicated schema + truncate fixture: simple and parallel-friendly.
  • Testcontainers via interop (your Java skills again): spin a real Postgres per CI run.
(import '[org.testcontainers.containers PostgreSQLContainer])

(def pg (doto (PostgreSQLContainer. "postgres:16")
          (.start)))
(def ds (jdbc/get-datasource {:jdbcUrl (.getJdbcUrl pg)
                              :username (.getUsername pg)
                              :password (.getPassword pg)}))

The REPL-driven loop, one last look

  1. Write a failing assertion right in a comment block / REPL.
  2. Implement; evaluate the function into the running process (Alt+Enter).
  3. (refresh) changed namespaces (or (reset) with Integrant).
  4. Rerun tests instantly — no rebuild, redeploy or context boot.

Capstone: build LinkVault

A bookmark manager — small enough to finish, wide enough to exercise all thirteen modules.

FeatureModules exercised
REST API: register/login (bcrypt via buddy-hashers), bookmarks CRUD, tag search01–05, 10

Suggested layout: monorepo with server/ (deps.edn project) and ui/ (shadow-cljs), sharing a shared/schemas.cljc file readable by both platforms — the .cljc reader-conditionals trick is Clojure's answer to sharing types across services.

Acceptance criteria
  • curl-able API returning JSON errors consistently (wrap-errors middleware)
  • Unauthenticated requests get 401; users only see their own bookmarks
  • Import/export of a JSON archive survives a property-based roundtrip test
  • UI works against a locally running server with hot reload
  • One-command startup: docker compose with Postgres + app

Summary · what you covered
  • clojure.test: deftest/is/testing/are plus thrown?; functions are values, so inputs and expected outputs are just maps.
  • Fixtures: use-fixtures with :each (like @BeforeEach) and :once (like @BeforeAll) wrap setup/teardown.
  • HTTP tests without Spring: ring.mock.request builds request maps; a Ring handler is testable directly, no server started — the payoff of Module 10.
  • Property-based testing: test.check generates random cases against invariants and shrinks failures to minimal examples (jqwik/Kotest props, natively).
  • Lint & format: clj-kondo (de-facto linter), cljfmt/zprint (formatter) and a CI pipeline keep refactors fearless.
  • Capstone: LinkVault — a full-stack app stitching REPL, collections, threading, state, interop, Ring + Reitit + Malli, next.jdbc + HoneySQL, and ClojureScript + Reagent together.

Exam · Module 13

1 · Inside clojure.test, which macro performs an assertion?
(is (= expected actual)) is the workhorse; (are ...) templates many similar assertions; thrown? tests exceptions.
2 · What do use-fixtures provide?
Equivalent to JUnit's @BeforeEach/@BeforeAll, expressed as functions receiving the test continuation.
3 · What makes test.check special?
Property-based testing with shrinking - same idea as jqwik/Kotest props, native to the ecosystem.
4 · Why can Ring handlers be tested without starting Jetty?
The transport layer is optional at test time - this is the payoff of the Ring design from Module 10.
5 · Which tool is the de-facto standard linter for Clojure projects?
clj-kondo reads source without executing it, catching arity errors, unused bindings and more - including inside your own macros.
