Control Flow & Threading Macros

Branches, loops without loops, error strategies — and the macros that turn nested code into readable pipelines.

Goals
  • Choose between if/when/cond/case correctly.
  • Iterate with loop/recur and for without stack overflow.
  • Handle errors with both exceptions and data.
  • Refactor nesting into pipelines with threading macros.

The branching family

(if (<= status 200) "ok" "problem")   ; one test, two branches

(when (> score 90)                    ; body only when truthy; nil otherwise
  (println "great!")
  :gold-tier)                         ; implicit do: multiple expressions OK

(if-let [user (find-user "ada")]      ; binds only when value is truthy
  (str "welcome " (:name user))
  "who?")

(when-let [{:keys [email]} payload]   ; when + let combined - very common
  (validate email))

cond, condp and case

;; cond = chain of test/expr pairs, like Kotlin `when`:
(defn grade [score]
  (cond
    (>= score 90) :A
    (>= score 75) :B
    (>= score 60) :C
    :else         :F))

;; case = compile-time constants, fast, throws if nothing matches:
(defn plan-price [tier]
  (case tier
    :free 0
    :pro  9
    :corp 99
    49))                       ; optional default expression

;; condp = binary-predicate chains:
(defn size-of [n]
  (condp < n
    10   :tiny
    100  :small
    1000 :medium
    :large))                   ; first clause whose comparison wins
Gotcha

case clauses are constants — they are not evaluated at runtime. (case x (* 2 1) :two ...) matches the symbolic form, not the number 2. Use cond/condp when clauses need computing.

Loops that aren't loops: loop/recur

The JVM lacks guaranteed tail-call optimization, so Clojure provides recur: a compiled jump back to the enclosing loop (or fn) head — constant stack, no overflow:

(defn factorial [n]
  (loop [acc 1
         n   n]
    (if (zero? n)
      acc
      (recur (* acc n) (dec n)))))   ; recur MUST be in tail position

(factorial 5)     ;=> 120
(factorial 50000) ;=> works fine - a plain recursive call would overflow

Honestly: you will write loop/recur less than you think — most iteration becomes map/filter/reduce (Module 06). It shines for state machines, parsers and retry logic.

Iteration helpers and comprehensions

(dotimes [i 3] (println i))              ; side-effecty counting

(doseq [u users]                          ; for-each over a collection
  (audit u))

;; for = list comprehension, LAZY result:
(for [x [1 2 3]
      y [:a :b]]                          ; nested iteration
  [x y])
;=> ([1 :a] [1 :b] [2 :a] [2 :b] [3 :a] [3 :b])

(for [n (range 20)
      :when (zero? (mod n 3))            ; filter inside the comprehension
      :let  [sq (* n n)]]
  [n sq])

Exceptions — and their alternative

(try
  (risky-operation)
  (catch Exception e
    (log/error (.getMessage e))
    {:error :internal})
  (finally
    (cleanup!)))

;; rich errors as data:
(throw (ex-info "payment declined"
                {:code 402 :provider "stripe"}))
(try (declined!) (catch Exception e (ex-data e)))
;=> {:code 402, :provider "stripe"}

;; resources close automatically - like try-with-resources / Kotlin use():
(with-open [rdr (clojure.java.io/reader "data.csv")]
  (count (line-seq rdr)))
Errors as data vs exceptions

Clojure code often returns {:error ...} or nil for expected failures and reserves exceptions for exceptional cases — closer in spirit to Kotlin's sealed Result<T> types, but with plain maps instead of a type hierarchy. Ring middleware (Module 10) converts exceptions into HTTP error responses centrally.

Threading macros: killing the pyramid of doom

Nested calls read inside-out. Threading macros rewrite them top-to-bottom. They are pure syntax transformations — no runtime cost:

;; before:
(str (clojure.string/capitalize (first (clojure.string/split "ada lovelace" #" "))))

;; thread-first  ->  inserts each step as the FIRST argument:
(-> "ada lovelace"
    (clojure.string/split #" ")
    first
    clojure.string/capitalize)
;=> "Ada"

;; thread-last  ->>  inserts each step as the LAST argument (collection fns):
(->> (range 20)
     (filter odd?)
     (map #(* % %))
     (take 4))
;=> (1 9 25 49)

;; some-> stops early on nil - the null-safe navigation operator:
(some-> order :customer :address :city clojure.string/upper-case)
;=> nil-safe at every step, unlike ->

;; cond-> threads conditionally:
(cond-> request
  token   (assoc :auth token)        ; assoc only when token is truthy
  debug?  (merge {:trace true}))

;; doto - repeated ops on the same object (Java builder style):
(doto (java.util.HashMap.)
  (.put "a" 1)
  (.put "b" 2))
Coming from Java/Kotlin

-> feels like method chaining (req.getUser().getAddress()) but works on any function, and ->> reads like Unix pipes or Java Streams chained steps — except it composes ordinary functions on ordinary collections. Kotlin's scope functions (let/run/also/apply) cover similar ground; here they are macros, not methods, so nothing special is required of your own functions.

Where this is used for real

Real handlers read like threaded pipelines: validate → authorize → persist → respond. Data-processing jobs are long ->> chains over lazy sequences (next module). some-> plus map lookups replaces entire null-check forests in integration layers.

Tasks

Task 1FizzBuzz, idiomatic. Return :fizz, :buzz, :fizzbuzz or the number itself for n = 15.
Solution 
(defn fizzbuzz [n]
  (cond
    (zero? (mod n 15)) :fizzbuzz
    (zero? (mod n 3))  :fizz
    (zero? (mod n 5))  :buzz
    :else n))

(map fizzbuzz (range 1 16))
Task 2Null-safe deep dive. Using some->, safely uppercase :city from (def o {:customer {:address {:city "berlin"}}}); verify it also returns nil for a missing customer.
Solution 
(some-> o :customer :address :city clojure.string/upper-case)
;=> "BERLIN"
(some-> {} :customer :address :city clojure.string/upper-case)
;=> nil
Task 3Refactor to pipeline. Rewrite (reverse (sort (distinct coll))) with ->>.
Solution 
(->> coll distinct sort reverse)
Task 4Countdown machine. Use loop/recur to print a launch countdown from 5, then return :liftoff.
Solution 
(loop [n 5]
  (if (pos? n)
    (do (println n) (recur (dec n)))
    :liftoff))
Task 5Comprehension grid. Produce all pairs [x y] from 0–9 where x < y using for with :when.
Solution 
(for [x (range 10)
      y (range 10)
      :when (< x y)]
  [x y])
;=> ([0 1] [0 2] ... [8 9])
Summary · what you covered
  • Branching: if, when/when-let, if-let, cond, condp and case (case is constant-matching and throws without a default).
  • Looping without loops: loop/recur gives constant stack space (tail call), and for/doseq handle collection iteration.
  • Error strategies: exceptions with try/catch/finally for control flow, plus errors as data — ex-info/ex-data carry structured details you can inspect in the REPL.
  • Threading macros: -> (threads first), ->> (threads last), some->/cond-> for safe/conditional pipelines, doto for side-effecting duties.
  • Looping is the exception, not the rule: prefer map/filter/reduce/for over an explicit loop.

Exam · Module 05

1 · What does recur do?
recur is a compiled tail call: constant stack space, no StackOverflowError. The compiler enforces its position in the body.
2 · (when x expr1 expr2) returns…
when wraps an implicit do: run all body forms only if the test is truthy, evaluating to the last one; otherwise nil.
3 · Which macro inserts each intermediate result as the LAST argument?
-> threads first (good for maps/objects), ->> threads last (good for collection transforms like filter/map).
4 · (some-> m :a :b) differs from (-> m :a :b) how?
some-> is the safe-navigation operator; plain -> happily threads nil along until something explodes.
5 · When does case fail at runtime?
case does constant matching and throws IllegalArgumentException without a default. cond/condp handle computed tests.
